# Public demo deployment

## Hosting architecture

The project is a Vite + React single-page frontend, an Express/Mongoose API, a
FastAPI analytics service, and MongoDB. `render.yaml` provisions the Vite static
site, the Node API, and a private AI service on Render. MongoDB is external
(MongoDB Atlas). The API and AI service use HTTPS/public TLS at the edge and
Render's private network for server-to-server traffic.

This blueprint is for a **public synthetic-data demo only**. Use a separate
Atlas database and credentials for it. Never point demo accounts at an
institution's database, never import real student data into the demo database,
and do not reuse the demo deployment as the production institution service.
Demo logins are authenticated by the API, have server-side roles, and are
read-only; their public passwords are not secrets or proof of identity.

## Deploy with Render

1. Push this repository to GitHub and create a MongoDB Atlas cluster. Create a
   database user with access only to a dedicated database named `eduai_demo`.
   Allow Render's outbound IPs in Atlas Network Access. If the chosen Render
   plan does not provide stable outbound IPs, Atlas may require a broader IP
   rule; use a long random database password and this isolated demo database.
2. In Render, choose **New → Blueprint**, connect the repository, and select
   the root `render.yaml`. Keep all three services in the `oregon` region so
   the API can reach the private AI service. The private AI and API services
   use paid Render plans; the static site can use the static-site plan shown
   by Render.
3. When Render prompts for `MONGODB_URI`, enter the Atlas URI with the demo
   database in its path, for example
   `mongodb+srv://<db-user>:<db-password>@<atlas-host>/eduai_demo?retryWrites=true&w=majority`.
   Enter `FRONTEND_ORIGIN` as the exact HTTPS origin Render assigns to
   `eduai-demo-web` (no path, e.g. `https://<site>.onrender.com`).
   `VITE_API_URL` is public build configuration, not a secret; enter the exact
   HTTPS API URL plus `/api`, e.g. `https://<api>.onrender.com/api`.
4. After `eduai-demo-ai` is created, open **Connect → Internal** and copy its
   internal hostname. Set the API service's `AI_SERVICE_URL` to
   `http://<internal-hostname>:8000` and save. This value stays server-side;
   never add AI credentials or MongoDB/JWT values to `VITE_*` variables.
5. After the API is healthy, open its Shell and run the following once to load
   the bundled synthetic CSVs and provision the read-only demo accounts:

   ```sh
   cd /app/backend
   npm run import:dataset
   npm run seed:demo
   ```

   The import is idempotent and updates source freshness timestamps. The seed
   refuses to run unless `DEMO_MODE=true` and the synthetic student `S0001`
   exists.
6. Open the `eduai-demo-web` URL. Use **Student demo** or **Admin demo** on
   the sign-in screen; each button fills the corresponding public credentials,
   then the browser still authenticates through the API. Confirm the demo
   banner appears and sign out before sharing the URL.

If Render Shell is unavailable, run the import and seed commands from a trusted
machine with Node dependencies installed, setting `MONGODB_URI`, `DEMO_MODE=true`
and a random `JWT_SECRET` in that process environment. Do not paste those values
into source files, command history, or a frontend `.env` file.

## Local production-build smoke test

From PowerShell at the repository root:

```powershell
npm ci --prefix backend
npm ci --prefix frontend
$env:VITE_API_URL = "https://your-deployed-api.example.com/api"
npm --prefix frontend run build
npm --prefix frontend run test
npm --prefix backend test
npm run build
```

`VITE_API_URL` is compiled into static browser files. Set it in the hosting
provider's **build-time** frontend environment and rebuild after changing it.
The default `/api` is intended for the Vite development proxy or a same-origin
reverse proxy; it is not a hardcoded localhost fallback.

## Configuration reference

| Variable | Where | Purpose |
| --- | --- | --- |
| `VITE_API_URL` | Frontend build environment; public | Deployed HTTPS Express API base URL ending in `/api`. Never put secrets here. |
| `MONGODB_URI` | API runtime; secret | Atlas URI for the dedicated demo database. |
| `JWT_SECRET` | API runtime; secret | Random signing key, generated by Render for this blueprint. |
| `FRONTEND_ORIGIN` | API runtime | Exact frontend HTTPS origin used by CORS. |
| `AI_SERVICE_URL` | API runtime | Render private AI service URL; not exposed to the browser. |
| `AI_SERVICE_TIMEOUT_MS` | API runtime | Timeout for Node-to-AI requests. |
| `DEMO_MODE` | API runtime | Must be `true` only for the separate synthetic-data demo deployment. |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | API runtime; secret | Optional provisioned institutional admin for a separate non-demo deployment; do not set these to the public demo account. |

The AI service currently uses deterministic, rule-based analytics and has no
third-party AI API key. If one is added later, configure it only on the
server-side service that needs it, never as a `VITE_*` variable.

## Feature and fallback behavior

- Dashboard, student records, interventions, student-success tools, reports,
  certificates and analytics use the authenticated API and database. Demo mode
  has no client-side fake login or local demo-data fallback.
- The bundled CSVs under `datasets/raw` are synthetic and are imported into
  MongoDB. The Docker image includes them at `/app/datasets/raw`; importer paths
  are resolved from the script location or `DATASET_DIR`, not the process
  working directory.
- AI-dependent insights require the private FastAPI service. When it is down,
  the UI displays an error state rather than fabricated scores.
- Session tokens expire after eight hours. Startup and direct-route refresh
  revalidate the token with `/api/auth/me`; expired sessions are cleared.
  Logout clears the browser session; JWT revocation is not implemented.
- React Router routes are rewritten to `index.html` by the Render static-site
  rule so refreshing a nested route serves the SPA.
- This repository does not currently implement a quiz/question-bank feature;
  quiz behavior cannot be verified as part of this deployment.

## Production institution deployment

Do not enable `DEMO_MODE` or deploy the public demo accounts against production
student data. Provision a separate API/database with `DEMO_MODE=false`, a unique
`JWT_SECRET`, tightly scoped `MONGODB_URI`, exact `FRONTEND_ORIGIN`, and
server-provisioned institutional accounts. Review institutional data
protection, retention, access control, and AI decision-support policies before
loading real student records.

No hosting account or deployment credentials were available in this
workspace, so no public URL has been deployed or externally verified.
